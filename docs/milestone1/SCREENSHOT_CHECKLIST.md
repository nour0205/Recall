# Three supporting screenshots

Use real GitHub file views after publishing the reviewed changes. These are
supporting evidence, not the final LinkedIn graphic.

| Screenshot | Open and display | Keep visible | Crop out | Why it helps |
|---|---|---|---|---|
| Project overview | Root `README.md`, title through architecture/scope | Recall description, confirmed stack, production/evaluation distinction | Browser account/avatar, tabs, bookmarks, unrelated UI | Shows a working project's scope without unsupported capability claims |
| Traceable measured results | `evaluation/MILESTONE_1_RETRIEVAL_EVALUATION.md`, section E: Evidence-group rescoring | File title/path, complete table, sentence identifying saved-ranking rescoring, nearby caveat about mode tradeoffs | Unrelated earlier tables, browser account/UI; avoid cutting off the caveat | Demonstrates explicit metrics and a qualified engineering conclusion |
| Reproducible benchmark | `evaluation/benchmarks/retrieval_v2.json`, case `retrieval_015` | Question, both atomicity/precision groups, acceptable document/chunk references | Adjacent cases, excessive legacy-label scrolling, browser account/UI | Proves manual evidence annotation and multi-part coverage rather than a cosmetic metric dashboard |

Do not screenshot `.env`, terminal commands containing credentials, local file
paths, cache folders, or private browser tabs. Use the repository views, not
local screenshots containing machine/account details. Never use old
`Pipeline2.png` as proof of the current architecture; it is a historical asset.
